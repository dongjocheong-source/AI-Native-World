LLM Knowledge System

1. 핵심 배경: 기존 RAG의 한계

일반적인 LLM 문서 활용 방식은 RAG(Retrieval Augmented Generation)입니다. 문서를 업로드하면 질문 시점에 관련 내용을 검색하고 답변을 생성합니다.

하지만 Karpathy가 지적하는 문제는 "지식의 축적이 없다"는 점입니다. 질문할 때마다 LLM은 원본 문서에서 다시 정보를 찾고 조합해야 하며, 이전 분석 결과나 문서 간 관계가 지속적으로 쌓이지 않습니다.

2. LLM Wiki의 핵심 아이디어

LLM Wiki는 검색 시스템이 아니라 "지식을 컴파일하고 유지하는 시스템"입니다.

  • 원본 자료를 읽는다
  • 핵심 정보를 추출한다
  • 기존 Wiki 구조와 연결한다
  • 새로운 정보와 기존 지식을 통합한다
  • 모순이나 변경 사항을 기록한다

결과적으로 Wiki는 시간이 지날수록 풍부해지는 지속 가능한 지식 자산이 됩니다.

3. 전체 구조

Raw Sources

논문, 기사, 이미지, 데이터 등 원본 자료

LLM Compile

LLM이 Markdown Wiki 생성

Persistent Wiki

문서 연결과 지식 구조 유지

Agent Query

축적된 지식 기반 질문 응답

4. Persistent Wiki 방식

Knowledge Compilation

새 문서가 추가될 때 단순히 색인하지 않습니다. LLM이 내용을 읽고 기존 지식 구조에 반영합니다.

Knowledge Connection

Entity Page, Topic Summary, Backlink 등을 생성하여 문서 사이의 관계를 유지합니다.

Knowledge Growth

새로운 자료와 질문이 추가될수록 Wiki가 점점 더 정교해집니다.

5. Idea File의 의미

Karpathy는 완성된 코드보다 "아이디어 파일"을 공유하는 새로운 방식을 제안합니다.

사용자는 이 문서를 자신의 LLM Agent(Codex, Claude Code 등)에 전달하고, Agent가 자신의 환경에 맞는 LLM Wiki를 구현하도록 합니다.

6. 활용 예시

  • 개인 연구 Knowledge Base
  • 논문 및 기술 자료 관리
  • 기업 내부 지식 Wiki
  • 프로젝트 히스토리 관리
  • 지속적으로 성장하는 AI Research Assistant

7. 기존 방식과 비교

RAGLLM Wiki
질문마다 검색지식 사전 컴파일
매번 새롭게 조합기존 지식 활용
축적 효과 제한시간에 따라 성장
